# CLAUDE.md

Правила разработки коммерческого iOS-приложения на React Native, Expo и TypeScript.

## Среда

- Разработка на Windows, без macOS: iOS Simulator и локальные сборки Xcode недоступны.
- Целевая платформа — iPhone.
- Проверка на физическом iPhone через Expo Go.
- Исходный код хранится в GitHub.
- Весь новый код должен работать в Expo Go. Если для задачи нужен нативный модуль вне Expo Go, сначала согласовать это.
- Перед созданием проекта и сменой версии Expo SDK проверять, какие версии поддерживает Expo Go на iPhone: проект должен открываться на устройстве.

## Продуктовое задание

- Проект — IRONVANT. Задание, реестр решений №001–104 и журнал конфликтов лежат в `docs/ironvant/`.
- Решения №105 и далее не утверждены.
- При конфликте действует порядок: последнее явное решение владельца, реестр решений, мастер-промпт, существующий код.
- Конфликты не решать молча, а записывать в `docs/ironvant/DECISION_CONFLICT_LOG.md`.

## Архитектура

- TypeScript со строгой типизацией.
- React Native и Expo как основа.
- Expo Router для навигации, если это соответствует проекту.
- Модульная архитектура и переиспользуемые компоненты.
- UI, бизнес-логика и данные разделены.
- Масштабируемость без ненужного усложнения.

## Дизайн

- Качество интерфейса уровня коммерческого iOS-приложения.
- Единая дизайн-система: цвета, типографика, отступы, размеры, скругления, тени, анимации.
- Поддержка разных размеров экранов iPhone.
- Соблюдение safe areas.
- Корректная работа с клавиатурой и длинными текстами.
- Единый стиль всех экранов.
- Нативные жесты и понятная навигация.
- Никаких произвольных дизайнерских решений в обход утверждённых макетов.
- Expo Skills и Frontend Design использовать совместно.

## Функциональность

- Все элементы интерфейса выполняют заявленные действия.
- Никаких неработающих кнопок, фальшивых функций и фиктивных результатов без явного обозначения.
- Предусматривать загрузку, пустые состояния, обработку ошибок и восстановление после сбоев.
- Проверять сохранение и восстановление данных.
- При реализации новых функций сохранять работоспособность существующих.

## Работа с Git

- Каждое изменение небольшое и контролируемое.
- Перед изменениями изучать затрагиваемые файлы.
- Не удалять работающую функциональность без согласования.
- Не переписывать весь проект ради локальной задачи.
- Не выполнять force push и другие разрушительные Git-операции.
- Для крупных изменений сначала предлагать план.

## Порядок работы над задачей

1. Изучить требования.
2. Проверить текущую реализацию.
3. Выбрать необходимые навыки Claude.
4. Продумать архитектуру.
5. Реализовать функцию.
6. Выполнить доступные автоматические проверки.
7. Проверить совместимость с Expo Go.
8. Сообщить, что необходимо проверить вручную на iPhone.

## Автоматические проверки

Запускать те, что применимы к проекту:

```bash
npx expo-doctor
```

```bash
npx expo install --check
```

```bash
npx tsc --noEmit
```

```bash
npx expo lint
```

Дополнительные зависимости устанавливать только при необходимости.

## Отчёт по завершении задачи

- Что реализовано.
- Какие файлы изменены.
- Какие тесты выполнены и с каким результатом.
- Что не удалось проверить.
- Есть ли ограничения Expo Go.
- Что нужно проверить на устройстве.
