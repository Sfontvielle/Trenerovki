# IRONVANT — Что нужно помимо промпта и как запускать разработку

Цель: передать Claude Code готовый контекст и затем вести **реальную поэтапную разработку**, а не получать бесконечные концептуальные обсуждения. Это рабочая инструкция владельцу проекта.

## 1. Что передать Claude Code

Обязательно:
1. `01_MASTER_PROMPT_FOR_CLAUDE_CODE.md` — роль, обязательные правила, порядок аудита и разработки.
2. `02_DECISION_REGISTER_001_104.md` — 104 согласованных решения и границы технического задания.
3. Доступ к **реальному репозиторию** проекта (предположительно `https://github.com/Sfontvielle/Trener`, обязательно подтвердить); текущие файлы, история, конфигурации и тесты.

По возможности: исходные скриншоты дизайна, макеты и фотографии-референсы 3D-модели, примеры желаемых анимаций, текущие Blender-файлы, договорённости по лицензиям, спецификации упражнений. Их нельзя заменить одной словесной инструкцией, если нужна точная визуальная копия.

## 2. Как начать работу в Windows

1. Открой рабочий каталог Git-проекта. До старта проверь незакоммиченные собственные изменения. **Ничего не удаляй и не откатывай для подготовки.**
2. Помести первые два `.md` файла в `docs/ironvant/` внутри проекта (это документация, а не изменение кода приложения). Если используешь архив, распакуй файлы оттуда.
3. Открой Claude Code в корневой папке репозитория (терминал либо соответствующая интеграция IDE). Не запускай из случайного домашнего каталога, иначе агент может проверять не тот проект.
4. Отправь текст из `01_MASTER_PROMPT_FOR_CLAUDE_CODE.md` начиная с `# НАЧАЛО ПРОМПТА`, либо попроси Claude Code прочитать файл целиком и выполнить инструкцию из него; проверь, что он также открыл `02_DECISION_REGISTER_001_104.md`.
5. **Первый выходной результат — аудит, а не новые экраны.** Запроси отчёты `REPOSITORY_BASELINE`, `ARCHITECTURE_MAP`, `REQUIREMENT_COVERAGE`, `TECH_RISK_REGISTER`, `INITIAL_BACKLOG`.
6. После просмотра аудита отправь `04_EXECUTION_AFTER_AUDIT.md` и утверди небольшой план задач, который реально допустим по результатам анализа. Дальше Claude Code выполняет изменения, тесты и отчёты по каждой вертикали.
7. Сохраняй все отчёты и изменения в репозитории, а не только в истории чата.

**Не нужно отдавать пароли Claude в чат.** Для доступа к сервисам использовать штатное подключение, локальную авторизацию и секреты окружения. Не позволять агенту писать ключи в репозиторий.

## 4. Что Claude Code сможет сделать сам, а что — нет

**Сможет при наличии окружения:** проверить репозиторий и код, подготовить архитектуру и backlog, писать React Native/TypeScript и Swift-код, создавать тесты и документацию, выполнять доступные сборки, готовить 3D-сцену через разрешённый Blender-инструментарий, формировать CI-конфигурации, устранять конкретные дефекты и создавать PR.

**Не может гарантировать без тебя и внешних ресурсов:** юридическую чистоту бренда, профессионально лицензированные ассеты, реальные научные/биомеханические проверки, выдачу прав Apple Developer, наличие macOS и физических устройств, оплату сторонних услуг, проверку пользовательского спроса, возможность публикации в App Store и неизбежную безошибочность всех AI-рекомендаций. Для этих пунктов нужны отдельные проверки и иногда оплачиваемые услуги специалистов.

**Один мастер-промпт не превращает задачу в одноразовую автоматическую сборку всего коммерческого продукта.** Он задаёт инженерный контракт, по которому Claude Code должен выполнять и проверять работу последовательно в рамках доступных сессий и ресурсов.

## 5. Контрольные точки, которые лучше лично принять

1. **Аудит** — Claude действительно изучил репозиторий и не повредил исходники.
2. **Базовая тренировка** — запись подходов и восстановление после перезапуска на реальном iPhone.
3. **Визуальный дизайн** — экраны соответствуют ожидаемым премиальным примерам, а не просто имеют похожие названия компонентов.
4. **3D-прототип** — реальная мускулатура, правильные суставы/мышцы и работа RealityKit на iPhone, без обещаний по непроверенному ассету.
5. **AI Coach** — полезные рекомендации, ограничения, память и пользовательское подтверждение изменений.
6. **Платежи** — Sandbox/TestFlight, отсутствие двойных начислений, восстановление и защищённый серверный ledger.
7. **Релиз** — тесты, политика приватности, лицензии, App Store Connect, мониторинг и возможность устранения критических дефектов.

## 6. Что специально пока не утверждено

- Вопрос №105 о конкретной общей синхронизации и следующий №106 о восстановлении **не утверждены**. Начинать реализацию с уже согласованного Local-First/Watch-подхода и пользовательского защищённого экспорта. Новое облачное хранение чувствительных данных — отдельное решение.
- Конкретные цены AI-кредитов, дата выпуска, бюджет, модель/провайдер AI, 3D-ассет, доступность названия IRONVANT — не определены окончательно.
- Нельзя считать, что исходный репозиторий уже на React Native или содержит RealityKit. Сначала аудит, затем безопасная стратегия перехода.

## 7. Что делать после отчёта аудита

Сначала ознакомься с `INITIAL_BACKLOG`. Не утверждай всё целиком без просмотра. Разреши Claude Code **первый ограниченный этап**: устранить критические ошибки целостности данных, сохранить имеющуюся базу, настроить сборку/тесты и реализовать сквозной процесс создания-проведения-восстановления тренировки. Используй `04_EXECUTION_AFTER_AUDIT.md` как шаблон следующей команды.

Если хочется максимально близко к режиму «отдал и он делает», работай по контрольным этапам: **одно утверждение очередного этапа — много небольших задач внутри него**, с отчётами и явными проверками. Не отключай подтверждения для платежей, разрушительных миграций и передачи персональных данных.
